# Task Manager API

A RESTful API for managing a to-do list, built as part of an Introduction to Backend Development with Node/Express lab.

## Stack

- **Runtime:** Node.js
- **Framework:** Express 5
- **Language:** TypeScript
- **Dev Runner:** tsx
- **Auto-restart:** nodemon
- **ID Generation:** uuid
- **Package Manager:** Yarn

## Project Structure

```
task-manager-api/
├── src/
│   ├── app.ts
│   ├── data/
│   │   └── tasks.ts
│   └── types/
│       └── types.ts
├── dist/
├── tsconfig.json
├── tsconfig.dev.json
├── nodemon.json
└── package.json
```

- `src/app.ts` — entry point, Express server setup, route definitions, and middleware registration
- `src/data/tasks.ts` — hardcoded array of seed tasks used as the in-memory data store
- `src/types/types.ts` — shared TypeScript type definitions
- `tsconfig.json` — TypeScript config for production builds via `tsc`
- `tsconfig.dev.json` — extends `tsconfig.json`, enables `allowImportingTsExtensions` for development
- `nodemon.json` — nodemon config that watches `src` and restarts using `tsx`
- `dist/` — compiled JavaScript output, generated by `yarn build`

## Prerequisites

- Node.js installed — verify with `node -v`
- Yarn installed — verify with `yarn -v`

## Setup

1. Clone or download the project folder
2. Navigate into the folder:
   ```
   cd task-manager-api
   ```
3. Install dependencies:
   ```
   yarn install
   ```

## Running the Project

**Development**
```
yarn dev
```
Starts the server with nodemon and tsx. The server restarts automatically on any `.ts` file change in `src`.

**Production**
```
yarn build
yarn start
```
`yarn build` compiles TypeScript to JavaScript in the `dist` folder. `yarn start` runs the compiled output.

## API Endpoints

Base URL: `http://localhost:3000`

### Get all tasks
```
GET /tasks
```
Returns an array of all tasks.

**Response `200`**
```json
[
  {
    "id": "uuid",
    "title": "Fix Login Bug",
    "description": "Resolve the issue where users are unable to log in after password reset.",
    "completed": false,
    "priority": "high"
  }
]
```

### Get a task by ID
```
GET /tasks/:id
```
Returns a single task matching the given ID.

**Response `200`**
```json
{
  "id": "uuid",
  "title": "Fix Login Bug",
  "description": "Resolve the issue where users are unable to log in after password reset.",
  "completed": false,
  "priority": "high"
}
```

**Response `404`**
```json
{ "message": "Task not found" }
```

### Create a task
```
POST /tasks
```
Creates a new task. `title` is required.

**Request body**
```json
{
  "title": "New Task",
  "description": "Optional description",
  "priority": "medium"
}
```

**Response `201`**
```json
{
  "task": {
    "id": "uuid",
    "title": "New Task",
    "description": "Optional description",
    "completed": false,
    "priority": "medium"
  },
  "message": "Task created successfully"
}
```

**Response `400`** — when `title` is missing
```json
{ "message": "Title is required" }
```

### Update a task
```
PUT /tasks/:id
```
Updates one or more fields on an existing task. Only `title`, `description`, `completed`, and `priority` are accepted. `id` cannot be changed.

**Request body** — all fields optional
```json
{
  "title": "Updated title",
  "completed": true,
  "priority": "high"
}
```

**Response `200`**
```json
{ "message": "Task updated successfully" }
```

**Response `400`** — invalid `priority` value
```json
{ "message": "Priority must be low, medium, or high" }
```

**Response `400`** — invalid `completed` value
```json
{ "message": "Completed must be a boolean" }
```

**Response `404`**
```json
{ "message": "Task not found" }
```

### Delete a task
```
DELETE /tasks/:id
```
Removes a task by ID.

**Response `200`**
```json
{ "message": "Task deleted successfully" }
```

**Response `404`**
```json
{ "message": "Task not found" }
```

## Data Model

```ts
type Task = {
  id: string;
  title: string;
  description: string;
  completed: boolean;
  priority: "low" | "medium" | "high";
}
```

## Middleware

**Request Logger** — logs the HTTP method and path of every incoming request to the console.

```
GET /tasks
POST /tasks
DELETE /tasks/uuid
```

## Notes

- Data is stored in memory. All changes are lost when the server restarts.
- The seed data in `src/data/tasks.ts` is loaded once at startup.
